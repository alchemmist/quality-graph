## Fixed product decisions

The consumer uses ordinary GitLab jobs without GitHub credentials. A separate
service project executes the trusted publisher without checking out consumer code.
Use job, merge-request and note events, not pipeline webhooks. Reconciliation
repairs missed events; a bounded watcher must be validated for resource use.

Results bind instance, execution project, target project/MR, SHA, pipeline, job,
graph, flow, operation and node. A retry has its own job identity. Old, conflicting,
missing or malformed evidence cannot establish current success. Apply approvals
only after admission and only to quality failures.

Keep GitHub Result v0 compatibility. GitLab must not import the GitHub package.
Support both node declarations and MR/branch operation flows. Reject unsupported
platform-specific settings explicitly. Do not overwrite unmanaged CI files.

The HTTP fake and real GitLab are separate test layers. Fake scenarios run in
process and over a container HTTP endpoint; real GitLab runs actual jobs and
webhooks. GitLab.com is not required for implementation or acceptance.

## Real GitLab test matrix

Clean install/init/generate/validate; MR/default/feature branch pipelines; no
duplicate full checks; success/failure/quality/cancel/skip; missing/malformed/stale/
conflicting artifacts; partial and full retries; new MR heads; authorized and
unauthorized commands; revoke and redelivery; note/label ownership; forks; delayed
publisher and recovery; credential isolation; installation from built wheels.

## Release contract

Release all five packages at one exact version. Add isolated `publish-gitlab`
with `pypi-gitlab` Trusted Publishing and include its wheel/sdist in the final
GitHub Release. Edit `qg.yaml`, regenerate workflows through Makefile targets,
and preserve historical migration fixtures. PR readiness does not imply a tag or
PyPI publication has occurred.

## Environment findings

The host is ARM64 with 24 GiB RAM and about 104 GiB available disk space.
The existing Podman machine has 2 GiB RAM. Podman refuses to run a second machine
concurrently, so the created but stopped `qg-gitlab` Podman machine is not used.
Use a dedicated Colima Docker profile instead; preserve the existing Podman VM.
Official GitLab CE 19.3.1 and Runner 19.3.0 images both provide ARM64 manifests.
